`hestia-phase-bridge-20260912-001` 经 reports/configs/scripts/tests/runs 名称检索
无重名。不能把前轮的 oracle 读出进步称作原生模型根因。

## 固定对照

### A. 原生 C 的事件对应

原生 1280 四噪声、全部 dev5 的左夹爪已知在 0–49 越过 0.5。对每个条件
读取它自己的预测事件前 19 槽至事件槽，与目标真实左事件前 19 槽至事件槽
对齐，比较双方完整关节、左右掌位置/朝向、夹爪。clock 对照均取 30–49。
baseline 和 ridge 使用前轮同一坐标下保存的 30 槽预测，clock 取首 20，
oracle 取 1–20（-19…0），所有方法的目标完全一致。每噪声先算误差。
这是全 dev 的目标知情诊断，train 原生 chunk 存在事件删失，不人为补值或
挑出子集宣称 train 泛化。预测事件不足 19 个前槽则拒绝运行。
若 native 在事件对齐后仍差于同权 oracle 常数，单一开合时机错误不足以
解释其对应误差；不能从代理 ridge 成功推定原生 C 已修复。

### B. 把条件读出恢复到同一原生时间目标

沿用原 45 场景、双物体坐标、前 100 帧标签与 train40/dev5。每条轨迹用
固定分段线性映射 `[frame0, true_left_onset, frame99] → [phase0,50,100]`，
在 101 个整数 phase 上对原始连续动作逐维线性插值。没有新数据读取。
对 canonical 轨迹作同一二次 ridge（物理动作组分开选择；沿用七值 alpha、
train 外层逐场景留一、内层五折和 seed 20260912）。保留关节/夹爪范围。

固定同一条预测 canonical 轨迹，只替换逆映射使用的 query onset：

- true oracle：真实事件时刻，使用未来标签，非部署。
- estimated：前轮已冻结的二次位置 → 左事件时刻预测，不再拟合或选参。
- constant：同一允许 donor 的事件时刻算术均值。

全部恢复至原生 0–49 的同一个目标，再算完整/首动作及位姿。不得按不同目标
分布的误差比较宣称改善。每个 onset 条件下同时给 canonical mean/median
恢复控制，防止把给答案带来的收益误认成几何读出收益；原始时域常数和
前轮原始时域 ridge 作为固定参照。预测事件须严格在 (0,99)，否则停止，
不 silently clip。另记录 target 自身 warp→unwarp 的插值误差，不设新接受门。

## 判据与预算

如果仅 oracle 恢复通过而 estimated 未通过，确认这个代理的阶段估计缺口；
若 oracle 恢复仍未共同超过对应常数，不能声称阶段已是充分根因。
“共同通过”需 train 外层留一及 dev 的左右关节、夹爪和左右位置/朝向均
胜过各自两种常数；单项改善分别保留。不得删场景、调方法或选 checkpoint。

相同固定镜像及原生资产身份，WSL Bash → Linux Docker 离线只读运行；
2 CPU/2 GiB，核心 180 秒、整体 600 秒，SHA/finite/schema/资源异常停止。
先合成插值端点、严格单调、事件删失及目标隔离测试，再运行并独立复核。
无模型 forward、policy optimizer、原始缓存行、hidden、SSH 或仿真 step。
所有 FK 是命令位姿；所有 oracle 都不能部署；结果须与原生根因置信度分开。
