# Hestia K/V 参数归属交叉检验预登记

名称 `hestia-parameter-crossover-20260912-001` 已检索无重名。当前只授权
本地准备；新的 CUDA 窗口尚未执行。上轮原生前缀已完成并受保护结束。

八臂同 CUDA 激活读出表明，两层 K/V 投影后仍可读取物体位置，但无法据
探针前后差异确认原生因果。下一条单轴是：**固定其余全部参数，只改变
cross-attention K/V 来自 640 还是 1280。** 在两个原 checkpoint 上分别
作互逆替换，得到两个端点及两个 hybrid，四项固定全部报告。

1. `base1280`：原 1280，180 个完整输出必须精确复现历史 C。
2. `base640`：原 640，180 个完整输出必须精确复现已取回 CUDA 640。
3. `base1280_kv640`：保持 1280，只在内存替换奇数层 1/3/5/7/9/11/13/15
   的 k_proj/v_proj 共 16 个 weight。
4. `base640_kv1280`：保持 640，互逆替换同一组 16 个 weight。

所有 checkpoint 文件、配置、processor/normalization/数据身份先核对；
逐 tensor 字节审计应确认冻结 VLM 在两端相同。只允许精确登记的 16 个
键，shape 必须 320×320、键与 dtype 对齐、finite；全参数前后摘要证明
其余参数未动，推理期间全部参数不再变化。不落盘合成权重、不训练。
互换只发生在新进程的模型副本；源权重和历史证据只读。

四项均使用原 40 train / 5 dev frame0、四个历史噪声、完整 50 槽、原 CUDA
运行时和 4090 D，共 720 forwards。控制输出先逐值核验，失败停止，不以
容差扩大、换设备或重训继续。固定顺序，两端通过后才运行 hybrid。每项
上限 180 秒，共享工作上限 900 秒，最迟 1200 秒受保护关机；无其他任务
才能启动，独立 watchdog，回传 SHA 验证后回执，不释放实例。

验收按相同目标分开报告 train/dev、左右关节/夹爪、完整/首动作及命令 FK
位置/朝向。各臂保留四个噪声和五个开发场景，不选择最优噪声或 checkpoint。
定义 `D = error(base1280)-error(base640)`；正 D 的组中计算正向恢复
`error(base1280)-error(base1280_kv640)`，及互逆损伤
`error(base640_kv1280)-error(base640)`，同时报告交互项与原始误差。
恢复和损伤都成立才支持该参数组对这一退化的双向因果贡献；只单向恢复
视为相容性/交互候选，不能证明唯一根因。D≤0 仍报告，不硬算恢复比例。

该检验定位 640→1280 的变化，不能单独解释两端均存在的全部泛化失败。
即使 hybrid 离线改善，也不选 checkpoint、不部署、不给新 Gate/M2。
若只有部分组改善，保留失败部分并继续缩小，不将局部改善冒充根因完成。
dev 已用于诊断，hidden 保持封存。

本地只作固定离线 Linux Docker CPU 合成替换/身份/门禁测试和权重字节审计，
2 CPU/2 GiB、300 秒。当前不加载完整 policy、不使用 SSH、不启动 GPU。
待所有可审查材料和本地检查完成，再请求当前带卡 SSH。
