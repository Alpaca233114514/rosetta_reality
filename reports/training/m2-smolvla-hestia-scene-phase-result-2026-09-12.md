# Hestia 初始场景—动作阶段检查：时机失配已确认，左腕仍有残差

本轮本地检查完成，得到两项新证据：**上一轮前 50 槽中的左夹爪“多预测开合”
实际主要是提前，四个场景都在稍后的标签中真实张开；固定双物体近邻不能
稳定预测这个时刻。给目标真实阶段作 oracle 对齐后，左臂关节整体出现相对
常数的收益，但左腕角仍显著失配。** 这还不是唯一根因或策略修复的证明。

本轮只读本地原缓存的 45 个非 hidden 场景前 100 帧动作，共 4500 行。沿用已
绑定 Hestia 图像的双物体坐标、原生 Action Contract projection 与 episode
split。前 50 槽重构目标和旧 C 数组的最大差为 `1.1920928955078125e-7`，通过
预先固定的 `atol=1e-6, rtol=0`；差异没有被写回旧数组。

## 1. 后续标签纠正了“未发生”的时间边界

开度仍按 0 闭合、1 张开，事件定义固定为首次达到 0.5；帧号零基，50 Hz。
实际标签来自 0–99；预测仍是历史 1280 checkpoint 在 frame 0 生成的 50 槽，
没有新增 forward 或 rollout。预测范围覆盖原四种固定噪声。

| episode | 实际左夹爪越阈帧 | 1280 预测越阈帧范围 | 相对真实时刻 |
|---:|---:|---:|---|
| 22 | 42 | 46–49 | 晚 4–7 帧（80–140 ms） |
| 13 | 67 | 47–49 | 早 18–20 帧（360–400 ms） |
| 7 | 51 | 46–49 | 早 2–5 帧（40–100 ms） |
| 33 | 60 | 45–49 | 早 11–15 帧（220–300 ms） |
| 45 | 57 | 45–48 | 早 9–12 帧（180–240 ms） |

这保留了此前“只有场景 22 的目标在 0–49 张开”的事实，但不能再将其余
场景理解为无需张开：它们稍后都执行了同类事件。所有 train40 和 dev5 的
左右夹爪也均在前 100 帧越阈。100 帧“是否发生”因此退化为常数标签；该
窗口 Brier=0 不代表视觉判别成功，更不是任务成功率。

场景 13 的提前量超过此前 ±200 ms oracle 窗口；33 也有此情况。此前有界
oracle 不能据此外推成“所有时序解释均已排除”。反过来，本轮也没有调整
Hestia 预测、放宽原门槛或证明更大时移能够修复完整轨迹。22 的偏差方向
相反，不能直接采用统一提前/延后的方案。

右夹爪真实越阈帧为 39/69/56/56/57；例如场景 22 的预测在前 50 槽仍未越阈，
而场景 33 已在 44–47 越阈。左右臂节奏也不能用一个全局事件时刻替代。

## 2. 相近初始场景的时间标签并不稳定

固定几何代理为 `[socket_x/640,socket_y/480,peg_x/640,peg_y/480]`。欧氏距离、
等权 3-NN 和 tie-break 均在新标签读取前固定。train 逐场景留一；dev 的 donor
始终是 train40，不按 dev 标签选 k、距离权重或规则。以下时间 MAE 使用全部
40/5 场景，因为这次 100 帧内事件均实测到，未补齐删失值。

| 集合 | 左开合时刻：3-NN / 常数 MAE（帧） | 右开合时刻：3-NN / 常数 MAE（帧） |
|---|---:|---:|
| train 留一 | 6.300 / 5.850 | 6.925 / 5.350 |
| dev5 | 9.200 / 7.600 | 7.200 / 6.400 |

常数为该查询允许 donor 的开合时刻中位数；train 自己的标签不进入参照。
3-NN 在这四个读数均未胜过常数。前 50 槽事件概率同样没有改善：左夹爪
train Brier 为 0.308333 / 0.239316，dev 为 0.311111 / 0.182500；右夹爪
train 为 0.172222 / 0.134122，dev 为 0.266667 / 0.162500，均按 3-NN / 常数
排列。完整混淆矩阵保留，未用偏向多数类的 accuracy 代替它们。

输入最近的五对 train 场景如下，排序只看坐标，包含事件相同的例子；全部
最近十对及坐标在 JSON 中。距离是上述归一化四维欧氏距离，并非米。

| train pair | 几何距离 | 左开合帧 | 右开合帧 | 前 50 槽左腕角两标签 MAE（rad） |
|---|---:|---|---|---:|
| 35 / 12 | 0.011228 | 53 / 42 | 57 / 49 | 0.138150 |
| 18 / 40 | 0.012411 | 51 / 44 | 53 / 56 | 0.091118 |
| 4 / 28 | 0.012853 | 67 / 67 | 74 / 62 | 0.124375 |
| 21 / 30 | 0.018277 | 57 / 60 | 61 / 53 | 0.199080 |

最接近一对的左开合相差 11 帧（220 ms）；还有左开合相同、右侧不同的对照。
已复看旧的三张图像拼图；几何提取仍对应图中的 socket/peg，但邻近图像不是
逐像素相同。本证据说明**固定二维位置代理下**存在局部监督分歧，不能证明
完整图像缺少其他信号，或将人的节奏认定为不可约噪声。

## 3. 关节轨迹并非完全没有空间对应

| 指标 | train 留一 3-NN / 最佳常数 MAE | dev5 3-NN / 最佳常数 MAE |
|---|---:|---:|
| 前 50 槽左腕角（rad） | 0.123423 / 0.107608 | 0.135434 / 0.100138 |
| 前 50 槽左关节（rad） | 0.056151 / 0.058166 | 0.055270 / 0.047658 |
| 50–99 槽左关节（rad） | 0.077975 / 0.110427 | 0.071403 / 0.079037 |
| 50–99 槽右关节（rad） | 0.094752 / 0.101160 | 0.119832 / 0.131996 |

同一个固定近邻在后半段左右关节都胜过各自常数，前半段左腕却在 train 留一
和 dev 均失败。结论应区分时间窗口和维度，不能总结为“初始几何完全没有
动作信息”。这是标签读出控制；Hestia 没有生成本轮所读的 50–99 槽预测。

## 4. 用真实阶段对齐后，左腕问题仍在

补充比较单独登记为 `hestia-scene-phase-alignment-20260912-001`。clock 控制
固定帧 50 为参考、窗口 30–59；event oracle 以每个场景**真实左夹爪开合帧**
为参考，取 −20…+9 的相同 30 槽。各近邻与常数都获得相同对齐；donor 集合
完全一致。query 的真实目标时间参与构造，以下不是可部署预测。

下表为 3-NN MAE / 两种常数中较小 MAE，比值小于 1 才表示该坐标内有相对收益。

| 集合 / 组 | clock | event oracle |
|---|---:|---:|
| train 留一 / 左腕角 | 1.0010 | 0.9827 |
| dev5 / 左腕角 | 1.7284 | 1.6893 |
| train 留一 / 左关节 | 0.7981 | 0.7908 |
| dev5 / 左关节 | 1.0420 | 0.8610 |

真实阶段对齐下，dev 左关节 3-NN MAE 为 0.065039 rad，对照 0.075538，出现
约 13.9% 的相对收益；左腕角仍为 0.129983，对照 0.076944，差约 68.9%。
它支持动作阶段错位遮蔽了部分左臂几何对应，但这一次左开合事件对齐不足以
解释左腕失配，也没有排除其他阶段参照或更复杂时间变形。

两个坐标下目标分布不同，不能将绝对 MAE 之差直接称为策略改善。左夹爪
在 oracle 中误差大幅降低还部分来自对齐的定义；dev 3-NN 仍略差于其最佳
常数（0.022241 / 0.021937）。左右夹爪未共同通过任何新增策略接受门。

## 5. 验证与可继续的证据边界

- 固定缓存 manifest `f3c03f7f...` 与完整 cache checksum 核对通过，图像审核、
  坐标、数据 revision/field/fps/action ordering 与历史 C 身份一致。
- 12 项场景/投影/过滤合成检查、4 项阶段对齐反例，以及 1 项真实缓存
  `pytest -m data` 通过；Ruff/格式通过。两组输出数组独立读回逐值相同。
- 核心检查 materialize 4500 条 action/timestamp 行；前置真实缓存检查另读取
  45 条 frame-0 action/state。没有读取未来 state 列、解码新视频帧或 materialize
  hidden 行。缓存完整哈希检验读取文件字节，与分析 hidden 样本不同。
- 本地固定离线 Linux 容器，2 CPU/2 GiB。场景检查约 8.71 秒，进程峰值 RSS
  1,165,848,576 bytes；oracle 数组分析约 0.29 秒、38,273,024 bytes。

源码为 `scripts/diagnose_hestia_scene_phase.py` 与
`scripts/diagnose_hestia_phase_alignment.py`；两个本日期 plan 的 MD/JSON 固定
方法与 SHA。原始新证据位于 `runs/hestia-scene-phase-consistency-20260912-001/`
和 `runs/hestia-scene-phase-alignment-20260912-001/`；前置测试及运行日志在
对应 preflight 目录。本报告同名 JSON 绑定这些结果、计划、代码及日志摘要。

下一证据重点缩到：**在阶段已知的条件下，左腕关节标签为什么仍缺少稳定的
几何对应**。可进一步区分关节解/姿态策略差异与初始观测表示不足；例如在
独立登记的纯运动学检查中对照末端位姿与关节轨迹。当前没有该检查结果，
不把“关节多解”当成已确认原因，也没有足够依据直接选择新损失或解冻方案。

本轮没有新模型 forward、policy optimizer、SSH、下载、提交、推送或删除。
此前 1280 固定结果、640/1280 曲线与失败记录均保留。视觉泛化尚未修复；
Gate 3/4 未新增测量，M2 未完成。
