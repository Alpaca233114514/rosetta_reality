# Hestia：关节失配不能直接等同于末端失配（2026-09-12）

本地纯运动学检查完成，视觉泛化**尚未修复**。真实阶段对齐后，固定几何
近邻的左末端位置误差优于常数约 24%，朝向误差仍差约 19%。先转换位姿
再平均也保留这一分化。因此，单纯更换为末端空间标签不能自动消除问题；
也不能根据左腕单关节误差认定所有末端目标都失配。

本结果补充 `m2-smolvla-hestia-scene-phase-result-2026-09-12.{md,json}`，
不替代主实验、CUDA 曲线或既有 Gate 证据。没有新策略、checkpoint 选择、
训练或 Gate 3/4，M2 未完成。

## 1. 比较的对象与身份

`hestia-command-pose-20260912-001` 只读取上一轮已保存的 train40/dev5
数组。clock 为帧 30–59；event oracle 为真实左开合帧前 20 槽至后 9 槽。
二维双物体坐标、固定 3-NN、train 留一和 dev 仅用 train donor 均不变；
已断言 donor 和关节均值与上一轮逐值相同。未读取原始缓存行或 hidden。

使用固定 image `sha256:fb3c1bbd...` 中 Gym-ALOHA 0.1.4、MuJoCo 3.8.1
的原生 insertion MJCF；22 个 asset 文件逐一绑定，asset tree SHA 为
`a31e1e61d50fcb142a1a8d141ae8a217e24d2e63344b409c130de45e45db7c8a`。
按合同名称、单位及范围映射两个六关节链，读取世界坐标中的左右
`gripper_link`。掌部祖先不含 finger joints；夹爪编码不参与腕部 FK。

这些位姿是**假定命令关节位置已到达时的计算值**，不是实际 state、

## 2. 位置有对应，左侧朝向的开发收益仍未成立

主比较先平均关节，再 FK。常数包括 train joint mean 与 median；下表
“最佳常数”只为描述性比较，取两种常数各指标的较小误差，不选择新策略。
位置为平均欧氏距离，朝向为 SO(3) geodesic，不混合米与弧度。

| 阶段坐标 / 集合 | 左位置 3-NN / 最佳常数（m） | 左朝向 3-NN / 最佳常数（rad） | 右位置 3-NN / 最佳常数（m） | 右朝向 3-NN / 最佳常数（rad） |
|---|---:|---:|---:|---:|
| clock / train 留一 | 0.031240 / 0.042889 | 0.158605 / 0.202381 | 0.023985 / 0.030330 | 0.160023 / 0.175912 |
| clock / dev5 | 0.031155 / 0.033414 | 0.163169 / 0.128852 | 0.032412 / 0.039550 | 0.169227 / 0.180542 |
| event oracle / train 留一 | 0.033545 / 0.046169 | 0.160808 / 0.216133 | 0.027327 / 0.034771 | 0.180179 / 0.193892 |
| event oracle / dev5 | 0.026763 / 0.035420 | 0.160336 / 0.134469 | 0.034179 / 0.041310 | 0.179298 / 0.206993 |

oracle dev 左位置相对收益约 24.4%，左朝向相对劣化约 19.2%。作为非线性
平均控制，先逐标签 FK，再平均位置与 SO(3) chordal mean，dev 左位置为
0.026598 / 常数 0.035107 m，左朝向为 0.159373 / 常数 0.137534 rad。
相对收益约 24.2%，朝向仍差约 15.9%；不是改一下平均顺序就解决。

两种阶段坐标的目标分布不同，不能把它们的绝对误差下降称为策略改进。
邻居读出优于常数也不是任务成功条件。

## 3. episode 13 与 45 指向不同的问题

以下保留每个 dev 场景的 oracle 左末端误差，对照统一使用 joint mean
常数，避免逐场景选择有利基线。

| episode | 3-NN / 常数位置（m） | 3-NN / 常数朝向（rad） |
|---|---:|---:|
| 22 | 0.017253 / 0.029250 | 0.128596 / 0.084828 |
| 13 | 0.022572 / 0.057737 | 0.128699 / 0.287807 |
| 7 | 0.028801 / 0.022895 | 0.085926 / 0.098474 |
| 33 | 0.028936 / 0.042900 | 0.177917 / 0.119720 |
| 45 | 0.036254 / 0.024319 | 0.280542 / 0.081515 |

episode 45 对五场景左朝向净劣化的贡献超过 100%；其他场景部分抵消它。
描述性去掉 45 后，剩余四场景的平均朝向误差为 0.130285 / 常数 0.147707
rad，方向反转。这是定位，**没有删除场景、调整 split 或改变接受条件**。

此前原生 Hestia 640→1280 左关节退化主要来自 episode 13；本检查是不同
预测器、窗口和坐标，13 在近邻的末端位置与朝向都优于常数。不能将两个
诊断的最大误差场景混称为同一个根因，或据此宣称原生 C 的 episode 13
已经被修好。也不能用单个腕角 MAE 替代整条运动链的朝向误差。

输入最近的一对 train 场景 35/12 在相位对齐后，命令左末端平均距离仍为
0.050135 m、朝向差 0.079662 rad；它们不是“同一末端位姿的两个关节解”。
最近十对全部保存在 JSON 中。输入邻近不等于图像相同，该事实也不证明
完整观测缺少动作信息或人的行为差异不可约。

## 4. 对修复方向的约束

现有证据支持将后续检查分成空间目标、运动阶段和朝向三个量，不能继续
用一个左腕平均误差解释全部失败。单纯增加训练步数、换旧 checkpoint、
复制几何近邻，或把所有关节标签转换成末端标签，都没有被验证为修复。

真正仍需验证的是：**使用部署时可获得的观测，能否在保留全部场景的
条件下同时改善阶段与朝向预测**。真实未来阶段只能作诊断上界，不能
流入策略输入；给 episode 45 单独规则或丢弃它也不成立。
若继续检验状态/历史条件或新的监督表达，应先在 train 的独立留出中
固定方法，再用原 dev 协议验证，并保留原生全 chunk 与首动作结果。
本检查没有足够证据直接选定一个新训练损失，也不把候选方案当作已修复。
