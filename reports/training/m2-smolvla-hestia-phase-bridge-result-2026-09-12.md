# Hestia：单独修正阶段不足以解释原生视觉泛化失败

继续追查得到两个否定性对照：**原生 C 即使对齐自己的预测开合事件，开发
朝向仍不能胜过同样获得真实阶段的常数；几何读出即使获得真实开合时刻，
恢复到原始完整 50 槽后也未共同通过。** 因此不能把上一轮条件性朝向收益
升级为“时机就是根因”。根因目标仍在进行中，本报告不是完成声明。

本地执行 `hestia-phase-bridge-20260912-001`，无新增模型 forward、训练、
原始缓存读取、hidden、SSH 或仿真 step。全部 dev5 保留，不选 checkpoint。
两个子对照的方法、范围与门槛在本日期同名 plan MD/JSON 中预先固定。

## 1. 原生预测自身也不是只差一个左开合时刻

原生 final1280 的所有 dev 图像在四噪声下都有左夹爪首次 0.5 越阈。
对每个条件取它自己事件前 19 槽至事件槽，匹配目标真实左事件前 19 槽至
事件槽。clock 对照固定为双方 30–49。没有外推预测 chunk，也没有把
没有事件的 train 条件删掉后冒充 train 验证；此原生对照范围就是全部 dev5。

每个坐标内，原生、固定几何 ridge、近邻和两常数看到相同的目标。下表
是四噪声的平均原生误差；常数取 mean/median 的较小值。

| 指标 | clock 原生 / 最佳常数 | event oracle 原生 / 最佳常数 | event oracle ridge |
|---|---:|---:|---:|
| 左掌位置（m） | 0.034489 / 0.029190 | 0.029683 / 0.033916 | 0.022200 |
| 左掌朝向（rad） | 0.151392 / 0.124184 | 0.154977 / 0.136225 | 0.113528 |
| 右掌位置（m） | 0.031218 / 0.036525 | 0.032675 / 0.038904 | 0.029713 |
| 右掌朝向（rad） | 0.176759 / 0.166604 | 0.207412 / 0.204277 | 0.167298 |
| 左关节（rad） | 0.074292 / 0.059403 | 0.072704 / 0.075684 | 0.049813 |
| 左夹爪（0–1） | 0.126871 / 0.092950 | 0.029195 / 0.019715 | 0.021016 |

左朝向的四个事件对齐原生误差为 0.167497/0.155271/0.139168/0.157971，
都差于两种同阶段常数。原生 C 与几何 ridge 的条件性对应因此有实测差别，
不能用后者替代 C 的输出证据。

对齐后左位置和左关节出现相对常数的收益，说明阶段确实解释了部分误差；
但它没有充分解释左朝向与左夹爪。clock/event 的目标分布不同，不能单用
两列绝对误差差值定义改进。这里用的是一个左事件参照，未排除所有可能
的非均匀时变机制，也没有把右臂未独立对齐的残差认定为不可修复。

## 2. 在同一个原始时间目标上移除 oracle

将全部45场景前100帧以 `[0,true_left_event,99] → [0,50,100]` 分段线性
映射成101个 phase 槽。二次 ridge 只在 train 拟合；外层逐场景留一，
内层五折选原七值 alpha，物理动作组分别选择。然后固定同一条预测
phase 轨迹，分别用真实事件、前轮冻结的位置预测事件、train 平均事件
还原到同一个原生 0–49 目标。所有原始数组与旧结果保持不变。

每个条件还有相同事件信息下的 phase mean/median 常数还原控制。它们在
oracle 条件也使用 query 真值，因此并非部署常数，但这是公平诊断参照。

| 开发完整指标 | 真实事件 ridge / 最佳同权常数 | 预测事件 ridge / 最佳同权常数 |
|---|---:|---:|
| 左关节（rad） | 0.042599 / 0.040497 | 0.054228 / 0.044582 |
| 右关节（rad） | 0.043315 / 0.046271 | 0.054873 / 0.051780 |
| 左夹爪（0–1） | 0.026294 / 0.023398 | 0.045373 / 0.043044 |
| 右夹爪（0–1） | 0.042049 / 0.037878 | 0.054754 / 0.051992 |
| 左掌位置（m） | 0.016726 / 0.017182 | 0.021948 / 0.018827 |
| 左掌朝向（rad） | 0.118424 / 0.095024 | 0.155715 / 0.117407 |
| 右掌朝向（rad） | 0.109322 / 0.111052 | 0.149541 / 0.136986 |

真实事件替代预测事件，确实能改善这个固定代理的误差，因为此表目标相同。
但真实事件下左关节、两夹爪和左朝向仍差于同权常数；训练留一也未全部
通过（例如 oracle 右关节 0.050240、最佳常数 0.049462）。所以既不能部署
这个预测事件代理，也不能说只差更准确的时刻就能解释全部失败。

使用 train 平均事件时的开发左右朝向为 0.165732/0.154911 rad；完整结果
保留所有方法、全部场景与首动作，不据 dev 选择一种条件。三个逆映射在
frame0 都指向 phase0，因此各条件的首动作预测相同；阶段替换本身不能
改变这种 frame0 首动作误差。这里的代理训练目标长度不同于前轮直接时域
ridge，二者仅作辅助参照，主要对照是同一 phase 预测的事件替换。

目标自身 warp→unwarp 的开发左关节平均误差约 0.000300 rad、左朝向
约 0.000923 rad，保留插值损失而不声称逐值可逆。本轮没有限幅元素，
结果不是 clipping 或旧标签覆盖造成的。

## 3. 验证与根因边界

- 17 项合成/运动学检查通过；Ruff 与格式通过。
- 原数据、代码、资产与目标身份通过 SHA/既定容差检查，新数组独立读回
  相同。另一个进程重算764个数值字段，原生匹配动作与 FK 误差逐值相同。
- 核心约3.29秒、峰值RSS176,549,888 bytes，在固定离线 Linux Docker
  中使用2 CPU/2 GiB。没有 runtime 修复、重试、训练或真实数据新增读取。

`reports/training/m2-smolvla-hestia-prefix-path-plan-2026-09-12.md`：只观察
现有1280 checkpoint，不改权重、只推理；原生输出必须精确复现历史CUDA。
