# Hestia：原生投影后仍可读物体位置，时序动作映射仍失败

本轮使用刚回传、完整输出精确复现 C 的原生 CUDA 激活。固定两层、投影
前后及 mean/2×2 pooling 的八臂全部报告，未按 dev 选择方法。
八臂的双物体位置在 train 外层留一和 dev5 均优于 mean、median；
但左右开合时机在 train 留一中均未优于两条常数，完整开发动作也没有
一臂共同改善全部物理组。**“所检查 K/V 投影彻底擦除物体位置信息”与
实测不符；当前证据仍不能确定哪组参数造成原生动作泛化失败。**

右开合有少数 dev 改善，但对应 train 留一不成立，不能据此挑选一臂。
左右开合 train 留一的较好常数分别为 5.85、5.35 帧；八臂均未共同击败
各自的 mean 与 median。完整左右关节 dev MAE 分别约 0.0497–0.0579、
0.0565–0.0621 rad，均劣于较好常数 0.04766、0.05275 rad。

真实事件 oracle 下，浅层 input 的左朝向 dev 为 0.13242/0.13368 rad，
略优于较好常数 0.13447；浅层 projected 为 0.13645/0.14356。深层 input
和 projected 左朝向也未击败该常数。右朝向各臂详见 JSON。这个前后差异
不能单独归因于信息丢失：投影方阵已有满秩证据，读出标准化、正则化、
pooling 与实际 attention 不等价；oracle 本身使用答案，不是可部署策略。

所有目标组独立以训练内五折选择同一七值 alpha 网格，train 再外层逐场景
留一，dev 仅使用 train40。归一化与标签选择都限制在允许 donor；共享
ridge 核只优化计算，不混合不同单位的目标。四个像素轴、各 dev 场景、
完整/首动作、命令末端位置和朝向均完整保留。没有读取 hidden 或原始样本。

14 项相关合成/FK 检查通过，包含原 ridge 数值对照、非连续输出组、
外层/开发标签隔离、常量特征和 token 象限顺序。独立重算 4,704 个数值
字段通过，原始/限幅数组分开保存并核对 clip 计数，NPZ 逐值 reload 通过。
核心耗时 9.812 秒、峰值 RSS 187,584,512 bytes，固定离线 Docker、2 CPU/
2 GiB。无 policy forward 或 optimizer。

输入/源码 SHA 与资源预算见同日期同名 plan MD/JSON；数组及机器结果在
`runs/hestia-prefix-readout-20260912-001/`，独立检查在对应 preflight 目录。
已反复用于诊断的 dev 不是独立确认集。根因工作继续，下一步需对原生参数
作受控交换以区分 K/V 投影和其余动作路径；不能用探针相关性替代该干预。
